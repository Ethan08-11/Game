下面按“玩家实际体验 + 前后端协作”的角度，把完整游戏流程顺一遍，不涉及代码。

# 1. 启动游戏

玩家打开 Electron 客户端。

客户端进入初始页面，通常是：

```text
开场 CG / 登录状态检查
```

如果本地没有有效登录状态，进入登录页面。

如果已经登录过，并且 token 仍有效，可以自动进入游戏大厅。

---

# 2. 登录 / 注册

玩家输入账号密码登录。

登录成功后：

- 客户端保存登录凭证。
- 客户端连接后端实时通信服务。
- 后端标记玩家在线。
- 后端通知该玩家的好友：这个玩家上线了。

此时玩家进入游戏大厅。

---

# 3. 游戏大厅

游戏大厅中玩家可以看到：

- 自己的用户名
- 积分
- 成就
- 排行榜
- 皮肤
- 任务
- 好友列表
- 开始游戏按钮

好友列表由后端返回。

好友列表中的好友默认来自数据库内置关系，不需要玩家手动添加。

每个好友显示：

- 好友名称
- 是否在线
- 当前状态

好友状态可能是：

```text
离线
在线空闲
组队中
游戏中
```

只有“在线空闲”的好友可以被邀请。

---

# 4. 点击开始游戏

玩家点击“开始游戏”。

客户端进入顾客情报页面。

---

# 5. 顾客情报页面

进入战斗前，游戏先展示本局顾客信息。

顾客数据从后端获取。

顾客类型可能包括：

## 善良稳重顾客

效果：

```text
霸凌者基础攻击 -2
```

顾客类型触发概率：

```text
40%
```

效果触发概率：

```text
40%
```

## 胆小怕事顾客

效果：

```text
霸凌者血量 +1
```

顾客类型触发概率：

```text
35%
```

效果触发概率：

```text
55%
```

## 焦虑难安顾客

效果：

```text
霸凌者基础攻击 +1
```

顾客类型触发概率：

```text
25%
```

效果触发概率：

```text
50%
```

## 闲逛双客

结伴闲逛却从不落单，偶尔会给两名护卫恢复血值。

效果：

```text
两名护卫各恢复 2 点血值（已倒下的不会因此复活）
```

顾客类型触发概率：

```text
约 9%（登场权重 10，低于其余顾客）
```

效果触发概率：

```text
20%
```

这个页面的作用是让玩家知道：

- 本局保护的顾客是谁
- 顾客有什么性格
- 顾客可能给战斗带来什么影响

玩家确认后，进入组队 / 邀请好友页面。

---

# 6. 组队 / 邀请好友

玩家进入组队页面。

页面显示：

- 在线好友列表
- 好友当前状态
- 房间区域
- 邀请按钮

玩家选择一个在线空闲好友，点击邀请。

---

# 7. 发送邀请

玩家 A 点击邀请玩家 B。

前端把邀请请求发给后端。

后端检查：

- A 是否在线
- B 是否在线
- A 和 B 是否是好友
- A 是否空闲
- B 是否空闲
- A 和 B 是否已经在其他房间或游戏中

如果检查通过，后端把邀请推送给玩家 B。

---

# 8. 好友收到邀请

玩家 B 客户端弹出邀请提示。

玩家 B 可以选择：

```text
接受
拒绝
忽略直到超时
```

## 如果拒绝

玩家 A 收到提示：

```text
对方拒绝了邀请
```

双方仍留在大厅或组队页。

## 如果超时

玩家 A 收到提示：

```text
邀请已超时
```

## 如果接受

后端创建双人房间，并把玩家 A、玩家 B 加入同一房间。

双方客户端都进入房间状态。

---

# 9. 双人房间

房间中显示两个玩家：

```text
P1：玩家 A
P2：玩家 B
```

房间状态包括：

- 玩家名称
- 玩家是否在线
- 玩家是否已选择部门
- 玩家是否已准备

此时双方需要选择部门。

---

# 10. 选择部门

两个玩家分别选择部门。

目前可选部门：

```text
销售部
采购部
```

规则建议是：

- 两名玩家不能选择相同部门。
- 一名玩家选择销售部后，另一名玩家只能选择采购部。
- 一名玩家选择采购部后，另一名玩家只能选择销售部。

部门决定该玩家的角色定位和个人牌组。

## 销售部

特点：

```text
攻击能力强
主要负责扣除霸凌者血量
```

初始血量：

```text
15
```

## 采购部

特点：

```text
防御能力强
主要负责保护队友
```

初始血量：

```text
20
```

部门选择完成后，双方点击准备。

---

# 11. 双方准备

玩家 A 点击准备。

玩家 B 点击准备。

后端收到双方准备状态后，开始创建正式对局。

前端不能自己判断“假装对方准备”，必须等待后端确认。

---

# 12. 后端初始化战斗

后端创建本局战斗。

初始化内容包括：

## 顾客

使用前面顾客情报页确定的顾客。

## 霸凌者

生成本局霸凌者。

当前规则中，霸凌者初始血量固定为：

```text
50
```

## 两名玩家

根据部门初始化：

```text
销售部：15 血
采购部：20 血
```

每名玩家初始：

```text
防御 0
员工调用机会 3
手牌 5 张
```

## 个人牌组

每名玩家本局拥有一套 20 张个人牌。

销售部牌组：

```text
销售部专属牌 + 通用牌
共 20 张
```

采购部牌组：

```text
采购部专属牌 + 通用牌
共 20 张
```

后端洗牌后，每名玩家抽 5 张作为第一回合手牌。

---

# 13. 进入作战页面

双方同时进入作战页面。

页面布局是：

```text
顾客 ｜ 销售部/采购部血条 ｜ VS ｜ 霸凌者
```

页面显示：

- 当前回合数
- 顾客
- 销售部血量
- 采购部血量
- 销售部/采购部防御值
- 霸凌者血量
- 当前玩家手牌
- 当前玩家员工调用机会
- 牌堆
- 弃牌堆
- 结束回合按钮

---

# 14. 牌堆查看

每名玩家本局有 20 张个人牌。

点击牌堆按钮：

- 不抽牌
- 不改变游戏状态
- 只查看当前玩家本局 20 张牌
- 以 4 × 5 的方式展示

注意：

```text
一局游戏有多个回合
每回合自动获得 5 张手牌
不能额外点击牌堆抽牌
```

---

# 15. 每回合开始

每个新回合开始时：

- 每名玩家自动获得 5 张手牌
- 每名玩家员工调用机会变为 3
- 如果有额外员工调用机会效果，则加上额外值
- 重置双方“是否结束回合”的状态
- 更新霸凌者本回合攻击值
- 触发或判定顾客效果

---

# 16. 顾客效果判定

每回合开始时，后端根据顾客数据判断顾客效果是否触发。

例如：

## 善良稳重顾客

如果效果触发，则：

```text
霸凌者基础攻击 -2
```

## 胆小怕事顾客

如果效果触发，则：

```text
霸凌者血量 +1
```

## 焦虑难安顾客

如果效果触发，则：

```text
霸凌者基础攻击 +1
```

## 闲逛双客

如果效果触发，则：

```text
两名护卫各恢复 2 点血值（已倒下的不会因此复活）
```

是否触发由顾客自身概率决定。

触发结果会广播给两个玩家。

例如页面提示：

```text
顾客机制触发：善良稳重顾客使霸凌者本回合攻击 -2
```

如果没有触发：

```text
顾客机制未触发
```

---

# 17. 玩家出牌阶段

每名玩家在自己的客户端上操作自己的手牌。

两名玩家可以理解为同一玩家回合内分别行动。

当前规则是：

- 玩家可以出任意张手牌
- 只要员工调用机会足够
- 已点击结束回合后不能继续出牌

---

# 18. 员工调用机会

每张牌都有费用。

费用就是：

```text
员工调用机会消耗
```

例如：

```text
费用 0：不消耗
费用 1：消耗 1 点
费用 2：消耗 2 点
费用 3：消耗 3 点
```

如果员工调用机会不足：

- 不能出牌
- 不扣资源
- 手牌不变

---

# 19. 出牌限制

## 销售部专属牌

只能销售部玩家使用。

## 采购部专属牌

只能采购部玩家使用。

## 通用牌

销售部和采购部都可以使用。

---

# 20. 出攻击牌

攻击牌作用目标默认是霸凌者。

玩家点击攻击牌后：

- 后端检查是否合法
- 扣除员工调用机会
- 卡牌进入弃牌堆
- 霸凌者扣血
- 广播最新状态

如果霸凌者血量降到 0，则立即胜利。

---

# 21. 出回血 / 加防牌

回血和加防牌需要选择目标。

目标可以是：

```text
P1（销售部）
P2（采购部）
```

玩家必须明确选择一个目标。

如果关闭目标选择弹窗：

- 不出牌
- 不扣员工调用机会
- 不触发效果
- 手牌不变

选择目标后：

- 后端检查是否合法
- 扣除员工调用机会
- 手牌进入弃牌堆
- 给目标回血或加防
- 广播最新状态

回血不能超过该玩家最大血量。

---

# 22. 防御显示

如果某个玩家当前防御大于 0，则在血条上方显示防御图标和数值。

例如：

```text
盾 3
15/15 体力
```

如果防御小于等于 0，则不显示防御图标。

---

# 23. 点击结束回合

每名玩家都需要点击一次结束回合。

玩家点击结束回合后：

- 该玩家本回合不能再出牌
- 该玩家剩余手牌进入弃牌堆
- 后端记录该玩家已结束
- 页面显示结束确认状态

例如：

```text
P1 已确认 / P2 未确认
```

只要还有一名玩家没结束，就不会进入霸凌者回合。

---

# 24. 两人都结束后

当两名玩家都点击结束回合后，后端检查：

```text
霸凌者血量是否为 0
```

如果霸凌者已经为 0，直接胜利。

如果霸凌者还活着，进入霸凌者攻击阶段。

---

# 25. 霸凌者攻击阶段

霸凌者攻击是同时作用于两名玩家。

例如霸凌者本回合攻击为 5：

```text
销售部受到 5 点攻击
采购部受到 5 点攻击
```

不是随机攻击其中一个玩家，也不是两人分摊伤害。

---

# 26. 扣血逻辑

每名玩家独立结算伤害。

规则是：

```text
先扣防御
防御不够的差值扣血
```

示例：

## 示例 1

```text
攻击 5
防御 3
血量 15
```

结算后：

```text
防御 0
血量 13
```

## 示例 2

```text
攻击 5
防御 8
血量 15
```

结算后：

```text
防御 3
血量 15
```

不过回合结束清算后，剩余防御也会失效。

---

# 27. 防御清算

霸凌者攻击结束后，防御效果会清算。

本回合剩余防御会失效并清空。

也就是说：

```text
这一回合加的防御，只保护这一回合
不会保留到下一回合
```

如果某些卡牌写明“下回合加防”，则那部分效果应在下一回合生效。

---

# 28. 持续效果

部分卡牌会有持续效果，例如：

```text
本回合造成伤害，下回合再造成伤害
本回合加防，下回合再加防
本回合回血，下回合再回血
下回合员工调用机会 +1
```

这些效果由后端记录。

进入下一回合时，后端自动结算对应效果。

---

# 29. 下一回合

如果没有胜负结果，则进入下一回合。

下一回合开始时：

- 回合数 +1
- 双方结束状态重置
- 双方员工调用机会重置
- 双方自动抽 5 张
- 顾客效果再次判定
- 玩家继续出牌

一局游戏会持续多个回合，直到胜利或失败。

---

# 30. 胜利条件

如果霸凌者血量降到 0，并且销售部和采购部都存活：

```text
玩家胜利
```

进入结算页面。

---

# 31. 失败条件

如果销售部或采购部任意一人血量降到 0：

```text
保护失败
```

进入结算页面。

注意：

```text
不是两个人都倒下才失败
任意一个玩家倒下就失败
```

---

# 32. 结算

战斗结束后，进入结算页面。

结算内容可以包括：

- 是否胜利
- 总回合数
- 总伤害
- 剩余血量
- 获得积分
- 战斗记录
- 卡牌使用情况

结算结果由后端保存，防止前端伪造积分或胜负结果。

---

# 33. 断线处理

因为是联机游戏，需要处理断线。

如果玩家短暂断线：

- 后端保留房间和战斗状态一段时间
- 另一名玩家看到“队友重连中”
- 玩家重新连接后恢复当前对局

如果超时未重连：

- 可以判定退出
- 或判定对局失败
- 或允许另一名玩家返回大厅

具体规则可以后续确定。

---

# 34. 整体流程总结

完整流程是：

```text
启动客户端
→ 登录
→ 建立在线状态
→ 进入大厅
→ 拉取好友列表和在线状态
→ 点击开始游戏
→ 查看顾客情报
→ 邀请在线好友
→ 好友接受
→ 创建双人房间
→ 双方选择部门
→ 双方准备
→ 后端初始化战斗
→ 进入作战页面
→ 每回合自动发 5 张牌
→ 玩家出牌
→ 玩家分别点击结束回合
→ 双方都结束后霸凌者攻击
→ 清算防御和持续效果
→ 进入下一回合
→ 直到胜利或失败
→ 结算
```

一句话概括：

```text
玩家在大厅邀请在线好友组队，双方选择销售部和采购部后进入作战；每回合各自动获得 5 张牌，用员工调用机会出牌保护顾客并攻击霸凌者；两人都结束后霸凌者同时攻击双方；任一玩家倒下则失败，霸凌者倒下则胜利。
```

# 项目配置与运行说明

本文档说明当前项目的本地运行方式：

- **MySQL、Redis、Nacos、RabbitMQ 运行在 Docker 中**
- **后端 Spring Boot 运行在本机**
- **前端 Vite + Vue 运行在本机**
- 局域网内其他电脑可通过你的主机 IP 访问前端页面

---

## 1. 项目整体结构

```text
前端（本机）      → Vite 5173
后端（本机）      → Spring Boot 8080
MySQL（Docker）   → 3308 → 容器 3306
Redis（Docker）   → 6379 或 6380（以你的 compose 为准）
Nacos（Docker）   → 8848
RabbitMQ（Docker） → 5672 / 15672
```

前端只负责页面展示和请求转发，业务逻辑主要在后端。

---

## 2. 本地开发环境要求

### 软件要求

- JDK 17
- Maven 3.9+
- Node.js 18+ / 20+
- npm 或 pnpm
- Docker Desktop
- MySQL 客户端工具（Navicat / DataGrip 等，可选）

### 网络要求

如果你要让同一局域网的其他人访问你的前端页面，需要：

- 保证你的电脑和对方在同一局域网
- 允许防火墙放行前端端口 `5173`
- 允许防火墙放行后端端口 `8080`
- 浏览器访问时使用你的局域网 IP，例如 `http://192.168.1.25:5173`

## 3. Docker 中的基础服务

当前项目依赖 4 个基础服务：

- MySQL
- Redis
- Nacos
- RabbitMQ

你可以使用仓库中的 `docker-compose.yml` 启动本地开发所需环境，也可以根据自己的实际端口配置启动。

### 默认端口对应关系

`.env.example` 中的默认配置如下：

```text
MYSQL_PORT=3308
MYSQL_DATABASE=wa_demo
MYSQL_USERNAME=wa_demo
MYSQL_PASSWORD=wa_demo
MYSQL_ROOT_PASSWORD=root

REDIS_PORT=6380
REDIS_PASSWORD=

RABBITMQ_PORT=5673
RABBITMQ_MANAGEMENT_PORT=15673
RABBITMQ_USERNAME=guest
RABBITMQ_PASSWORD=guest
RABBITMQ_VHOST=/

NACOS_PORT=8849
NACOS_GRPC_PORT=9849

BACKEND_PORT=8080
FRONTEND_PORT=80
```

> 注意：实际启动时，请以你最终使用的 `docker-compose` 文件和端口映射为准。

## 4. 后端配置说明

后端配置文件位于：

```text
wa-demo-service/src/main/resources/application.yml
```

### 4.1 MySQL

默认读取：

```yaml
spring:
  datasource:
    url: jdbc:mysql://${MYSQL_HOST:127.0.0.1}:${MYSQL_PORT:3308}/${MYSQL_DATABASE:wa_demo}
    username: ${MYSQL_USERNAME:root}
    password: ${MYSQL_PASSWORD:root}
```

因此如果 MySQL 跑在 Docker 中，并且端口映射为 `3308:3306`，那么后端本机运行时默认就能连上：

- 主机：`127.0.0.1`
- 端口：`3308`
- 库名：`wa_demo`

### 4.2 Redis

默认读取：

```yaml
spring:
  data:
    redis:
      host: ${REDIS_HOST:127.0.0.1}
      port: ${REDIS_PORT:6379}
```

### 4.3 RabbitMQ

默认读取：

```yaml
spring:
  rabbitmq:
    host: ${RABBITMQ_HOST:127.0.0.1}
    port: ${RABBITMQ_PORT:5672}
```

### 4.4 Nacos

默认读取：

```yaml
spring:
  cloud:
    nacos:
      discovery:
        server-addr: ${NACOS_SERVER_ADDR:127.0.0.1:8848}
      config:
        server-addr: ${NACOS_SERVER_ADDR:127.0.0.1:8848}
```

如果你当前使用 Nacos 作为配置中心或注册中心，请确认 Docker 中的 Nacos 服务已经启动。

## 5. 前端配置说明

前端项目位于：

```text
Game_Frontend
```

### 5.1 Vite 开发服务

前端配置文件：

```text
Game_Frontend/vite.config.ts
```

当前关键配置：

```ts
server: {
  host: '0.0.0.0',
  port: 5173,
  proxy: {
    '/api': {
      target: 'http://192.168.1.25:8080',
      changeOrigin: true,
    },
  },
},
```

含义：

- `host: '0.0.0.0'`：允许局域网访问
- `port: 5173`：前端开发端口
- `/api` 会代理到后端 `8080`

### 5.2 注意事项

当前只代理了 `/api`，所以：

- `/api/...` 请求会转发到后端
- `/images/...` 这类静态图片路径不会自动代理到后端

如果前端页面里直接使用后端图片地址，请确保图片 URL 指向后端真实地址，例如：

```text
http://192.168.1.25:8080/images/cards/Card_Carl.png
```

不要写成 `localhost`，否则局域网其他电脑会访问到它们自己的本机。

## 6. 启动顺序

建议按照下面顺序启动。

### 第一步：启动 Docker 基础服务

在项目根目录执行：

```powershell
docker compose up -d
```

如果你的环境使用的是其他 compose 文件，请按实际情况启动：

```powershell
docker-compose -f docker-compose.yml up -d
```

启动后建议检查容器状态：

```powershell
docker ps
```

确认 MySQL、Redis、Nacos、RabbitMQ 都已经正常运行。

---

### 第二步：启动后端

进入后端模块目录：

```powershell
cd wa-demo-service
```

启动 Spring Boot：

```powershell
mvn spring-boot:run
```

或者在 IDEA 中直接运行 `DemoApplication`。

### 后端启动后验证

浏览器访问：

```text
http://127.0.0.1:8080/actuator/health
```

如果你是局域网访问，也可以使用（前提是连接的是hand in hand的网络/当然也可以连接其他网络，然后改对应的配置）：

```text
http://192.168.1.25:8080/actuator/health
```

---

### 第三步：启动前端

进入前端目录：

```powershell
cd Game_Frontend
```

安装依赖：

```powershell
npm install
```

启动开发服务：

```powershell
npm run dev
```

前端启动后默认访问：

```text
http://127.0.0.1:5173
```

局域网内其他设备访问：

```text
http://你的局域网IP:5173
```

例如：

```text
http://192.168.1.25:5173
```

## 9. 常见问题

### 9.1 前端能打开，但接口请求失败

检查：

- 后端是否已启动
- 后端端口是否是 `8080`
- Vite 代理是否指向正确的后端 IP
- 浏览器是否访问了正确地址

### 9.2 图片访问失败

如果前端里图片路径是 `/images/...`，浏览器可能会请求前端端口 `5173`，而不是后端 `8080`。

你可以直接在浏览器里验证后端图片是否可访问：

```text
http://192.168.1.25:8080/images/cards/Card_Carl.png
```

如果这个地址能打开，说明问题出在前端引用路径或代理配置，而不是后端静态资源本身。

### 9.3 局域网其他人打不开前端

检查：

- `vite.config.ts` 是否使用了 `host: '0.0.0.0'`
- Windows 防火墙是否放行 `5173`
- 对方是否和你处于同一局域网
- 你访问时是否使用了正确的本机 IP

### 9.4 后端连接不上 Docker 中的 MySQL / Redis / RabbitMQ

检查：

- Docker 容器是否正常运行
- 端口映射是否与 `application.yml` 一致
- 环境变量是否覆盖了默认值
- 是否使用了正确的数据库用户名密码

## 10. 推荐的本地开发流程

如果你只是自己开发，推荐这个顺序：

1. 启动 Docker 中的 MySQL、Redis、Nacos、RabbitMQ
2. 在 IDEA 中启动后端
3. 在 `Game_Frontend` 中启动前端 `npm run dev`
4. 浏览器访问前端地址进行测试
5. 局域网测试时使用本机真实 IP
